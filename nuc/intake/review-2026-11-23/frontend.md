# Novashare: user-facing review (2026-11-23)

Scope: the Drop page (`portal.py`), the /sending page and the horizon picture (`atomic_ui.py`, `themes.py`), the
manifest and the fallback result page (`share.py`), plus the screenshots in `D:\overnight\2026-11-22\horizon\`.
Read-only review. Nothing was edited or run against a live server. Checklists used: frontend-design (one clear
identity, plain copy, restraint, a quality floor) and ui-ux-pro-max:design (consistency, state feedback, mobile
tap targets, readability).

## Summary
1. The /sending page with the collapsing star is good work: one strong picture tied to real progress, calm copy, and it respects reduced motion. Keep it.
2. The rest of the app still calls itself "Drop", and the page people open most (the Drop page) looks like a different app and shows build notes ("T0872, 2026-11-18", "Proton Pass", "VPN on the Pi").
3. Fix the name and the copy first (cheap, high payoff). Then make the error and "nothing to send" states readable, and bring the Drop page into the same look.

## Keep (works well)
- **One strong picture tied to real progress.** The star-to-horizon collapse reads `aria-valuenow` and does not touch the engine (`themes.py:155-166`). It also runs backward on a retry. The screenshots `hz-g00` → `hz-g35` → `hz-g70` show a clear, readable collapse.
- **Plain-words results.** `Atomic.plain` (`atomic_ui.py:134-158`) turns server statuses into sentences such as "Filed: a book on Casey's shelf." and "Already there: this exact file was sent before…".
- **Honest status text.** "Signal lost" and "The server is busy" are now separate messages (`atomic_ui.py:340-341`), and each says "your progress is kept".
- **Reduced motion.** It is handled on every layer: no rAF spin loop, no gulp, and no transitions (`atomic_ui.py:253,311`, `themes.py:131`).
- **Phone basics are right.** Tap targets are 44-48 px, there is a visible focus ring, body text is 16 px, `viewport-fit=cover` with safe-area padding is set, and the numbers use tabular figures.
- **The link field validates gently.** Errors appear only after the person has typed (`:user-invalid`), the message gives an example, and errors use an icon plus text, not color alone (`portal.py:132-141, 330-337`).
- **Identity comes from the sign-in, not a dropdown** (`portal.py:11-22`). That is one less wrong choice for people to make.
